# Security and privacy

This is a static website. It has no author login, submission upload form, database or mailbox integration. The editorial office receives manuscripts by email and is responsible for protecting that mailbox, its attachments and its confidential records.

Everything committed to the public repository or included in the generated website must be suitable for public release. Never include reviewer reports, unpublished submissions, private correspondence, credentials or hosting tokens. Publish only the editor-approved final PDFs and metadata for which the journal has permission.

Check final PDFs before release. A file extension alone does not establish that a file is safe, accessible or free of unintended metadata. Keep public downloads and external links accurate, and avoid unnecessary scripts or third-party tracking.

Report website problems to a maintainer using a verified published contact. If a report contains sensitive details, use a private reporting channel when available; do not put secrets or confidential manuscripts in a public issue. A dedicated reporting contact still needs to be confirmed before launch.

The journal operator should protect the domain, repository, host and mailbox accounts, maintain recoverable copies, and review access when responsibilities change. The static build does not provide email security, automatic backups or incident response services.
